# 场地调研 Agent：失败模式清单

> 范围：City of Ithaca, NY 的选址问题（分区、高度、用途、历史街区、洪水、公交）。
> 版本：v3（2026-10-27）。所有“真实触发”均来自对公开服务的实际调用，不是假设。
> 评测：19 个场景（7 个自然问题、9 个故障注入、2 个一致性复跑、1 个无 LLM 基线），v3 全部 74 项检查通过。

---

## 1. 设计原则

1. **空结果不是否定。** “查询返回 0 条”只能说明“这个源没查到”，不能写成“不在洪水区”。所有工具返回 `ok | empty | error | degraded | unverified` 五态，而不是“有数据/没数据”两态。
2. **确定性的事不交给 LLM。** 地理计算、规则表解析、容积估算都用代码完成；LLM 只负责规划和把证据写成人话。这样每个数字都能追溯到一条证据。
3. **结论强度不能超过最弱的关键证据。** 置信度上限 = min（位置、宗地、分区、辖区证据的置信度，规则证据平均置信度）。上限低于 0.5 时禁止输出“可行/不可行”。
4. **降级要让用户看得见。** 每次降级都会生成一条带来源的证据（例如“洪水查询失败，结果缺失”），回答里必须引用它，而不是悄悄省略。
5. **护栏本身也是分类器。** 它会误报，所以需要自己的测试集和误报成本统计（见 FM-23）。
6. **兜底不能吞掉缺陷。** catch-all 异常处理会把代码 bug 变成“看起来正常但少了一块”的回答（见 FM-24）。

---

## 2. 降级阶梯（以洪水查询为例）

| 级别 | 来源 | 置信度 | 触发下一级的条件 |
|---|---|---|---|
| L0 | [FEMA NFHL 有效洪水图层](https://hazards.fema.gov/arcgis/rest/services/public/NFHL/MapServer) 点查询 | 0.9 | 超时 / 5xx / 进程内熔断已打开 |
| L1 | [Esri USA Flood Hazard 镜像](https://services.arcgis.com/P3ePLMYs2RVChkJx/arcgis/rest/services/USA_Flood_Hazard_Reduced_Set_gdb/FeatureServer) | 0.6 | 返回空时先做覆盖探测：Ithaca 范围内要素数 = 0，说明是镜像没覆盖，不是“无洪水区” |
| L2 | 宗地属性 `FZONE` / `FIRMPANEL` | 0.2 | 字段引用旧版 FIRM 面板 0003B；[Tompkins County 新版 FIRM 已于 2025-06-18 生效](https://www.tompkinscountyny.gov/Government-Resources/Flood-Information) |
| L3 | `unverified` + 人工核对指引 | 0.0 | 回答必须写“未能核实”，并禁止任何“无洪水风险”类表述 |

同样的阶梯也用于地理编码（Census → Nominatim → 失败即停止）和宗地定位（空间吸附 0/15/35 m + 门牌号与奇偶校验 → 评税名册地址反查 → 停止并说明）。

严重度：**S1** = 可能导致用户做出错误投资/设计决定；**S2** = 回答质量明显下降；**S3** = 只影响成本或体验。

## 4. 成本统计

**计量方式。** 每个步骤都是一个 span，记录耗时、token、HTTP 次数和美元成本。LLM 价格按假设单价计算（haiku 每百万 token 输入 $1 / 输出 $5，sonnet 输入 $3 / 输出 $15），可在 `agent/core.py` 修改。每次 LLM 调用前按最坏情况（max_tokens 全部用满）预留预算，超出就不发起调用。

**v3 评测结果（19 次运行）**

| 指标 | 数值 |
|---|---|
| 19 次总成本 | $0.585 |
| 完整 LLM 回答的中位成本 | $0.043 |
| 单次最高成本 | $0.082（F6：注入幻觉后重写一次） |
| 无 LLM 基线 | $0 / 1.3 秒，结论与 LLM 版一致 |
| 超出辖区 / 找不到地址 | $0.010–0.026（提前停止） |
| 澄清问题 | $0.002 |
| 合成步骤占总成本 | 94%（$0.552） |
| 合成步骤占总耗时 | 77%（243 秒，工具调用只占 29 秒） |
| 失败或空结果工具浪费的时间 | 最多 4.6 秒（F1 洪水超时） |

**结论。** 成本几乎全部在最后的回答合成，不在工具调用。所以省钱的方向是：（1）护栏误报导致的重写（每次约 +$0.04，接近翻倍）；（2）在出现阻断性问题（超辖区、找不到地址）时提前停止；（3）对低风险问题用无 LLM 的模板答案。

## 5. 产品指标

| 指标 | 定义 | v3 |
|---|---|---|
| 危险错误率（false-safe） | 证据未核实，但回答给出“安全 / 可行”类结论 | 0 / 19 |
| 引用有效率 | 回答中的 [E#] 都能对应到真实证据 | 19 / 19 |
| 需人工核实比例 | 至少一个关键项为 `unverified` / `degraded` | 16 / 19（主要是规则时效和 PDF 噪声，这是现实情况，不应为了指标好看而隐藏） |
| 护栏自然触发精确率 | 非注入运行中，护栏拦截且确实有问题 | 0 / 3 条（2 次运行，全部是误报，已修复） |
| 每答成本 / 耗时 | 完整回答的中位数 | $0.043 / 约 22 秒 |
| 一致性 | 同一问题复跑，结论与关键数字一致 | 3 / 3（N1、R1a、R1b） |

“需人工核实比例”高不一定是坏事。对选址这种高代价决策，更重要的是把不确定性说清楚，并告诉用户去哪里核实。

## 6. 迭代记录

| 版本 | 评测结果 | 发现的问题 | 修改 |
|---|---|---|---|
| v1 | 8 / 19 场景全部通过（50 / 61 项） | 评测脚本自己误报；跨分区宗地只解析了一个分区；预算熔断事后才检查，实际花费是上限的 22 倍；一次自然运行中护栏同时误报 2 条，该次成本 $0.080、耗时 51 秒（正常约 $0.042） | 评测检查复用护栏函数；跨分区并集解析；调用前预留预算；护栏增加免责语境识别 |
| v2 | 18 / 19（61 / 62 项） | F8 失败，追查后发现公交工具在服务进程里一直抛 `KeyError`，被兜底吞掉；LLM 有时不规划公交 | 修复缓存冲突；异常生成证据；必查清单策略；评测增加“无静默工具异常” |
| v3 | 19 / 19（74 / 74 项） | F1 出现新的护栏误报（“不能解读为‘不在洪水区’”），成本 $0.082 | 扩展免责语境，引号容错，不跨分句；护栏测试 10 / 10。修复后 F1 成本降到 $0.043 |

## 7. 尚未解决的问题

- **评测集太小。** 19 个场景只能证明机制有效，不能证明在真实流量下的准确率。下一步是收集 100 个以上真实问题，并请规划师标注答案。
- **只覆盖一个城市。** 数据源、叠加区列表和 PDF 解析规则都针对 City of Ithaca，换城市需要重新做数据源适配。
- **用途映射（FM-27）。** “咖啡馆”“联合办公”这类说法和条例用途分类之间需要一张经过审核的映射表。
- **提示注入（FM-26）** 还没有防护。
- **护栏靠正则。** 精确率已经修好，但召回率只在 10 条用例上验证过，换说法可能漏判。可以考虑用小模型做二次分类，但要算清楚成本。

## 8. 简历与面试要点

**简历（可直接使用）**

- 设计并实现一个场地调研 Agent（规划 → GIS / 规划文件 / 公交工具 → 确定性计算 → 带引用的回答），在 City of Ithaca 真实公开数据上运行，全程记录工具调用链、延迟和成本。
- 整理 27 类 Agent 失败模式（其中 23 类在真实服务调用中观察到），为每类定义检测信号、降级策略和用户可见表现；用 19 个场景、74 项检查的评测集推动三轮迭代，通过率从 8 / 19 提升到 19 / 19。
- 建立每答成本核算和调用前预算预留，发现 94% 的成本来自回答合成，护栏误报会让单次成本接近翻倍；修复后完整回答中位成本 $0.043，危险错误率 0 / 19。

**面试可以讲的三个故事**

1. **“空结果不是否定”。** Esri 洪水镜像在 Ithaca 返回 0 条。如果直接用，Agent 会说“不在洪水区”。我加了覆盖探测：同一镜像在 Binghamton 附近有 367 个要素，在 Ithaca 是 0，说明是没覆盖，不是没风险。这类错误最危险，因为它看起来像一个干净的答案。
2. **“兜底吞掉了 bug”。** v2 只有一个场景失败。追查后发现公交工具一直在报错，只是被 catch-all 变成了普通错误，回答里悄悄少了一块。教训是：容错和可观测必须一起做，异常要进入证据和评测，不能只进日志。
3. **“护栏也会错”。** 非注入运行中护栏拦截了 3 条，全部是误报，每次重写多花约 $0.04 和 20 秒以上。我把真实误报加入护栏单元测试，把护栏当成分类器来评估精确率和成本，而不是默认“多一道检查总是好的”。
