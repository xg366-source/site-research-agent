跑通只是起点。
这个 Agent 的重点是出错时怎么办。

用户问一个选址问题，Agent 自己规划步骤：查分区和宗地 GIS、读规划 PDF、查洪水和公交、做确定性计算，最后给出带引用的回答。每一步都记录状态、耗时和成本；工具返回空、超时或结果可疑时，按预设阶梯降级，并把降级写进回答。

降级阶梯：洪水查询

这是最容易“看起来答对了”的一项。镜像服务在 Ithaca 返回 0 条，如果直接采用，Agent 会说“不在洪水区”。

    新版 FIRM 已于 2025-06-18 生效（Tompkins County），宗地字段引用的是旧版面板，所以 L2 只给 0.2 的置信度。

    成本统计

    每个步骤单独计量 token、HTTP 次数、耗时和美元成本；LLM 调用前按最坏情况预留预算，超出就不调用。价格按假设单价计算。

    成本去了哪里

    回答合成占 94% 的成本和 77% 的耗时，工具调用本身几乎免费。所以真正该优化的是：避免不必要的重写、遇到阻断问题时尽早停止。

    三轮迭代

    每一轮都是评测先暴露问题，再改代码。最有价值的发现都不在“happy path”上。

    护栏误报：一个真实例子

    v2 的 F1 运行里，LLM 的第一版回答其实写得没问题，但被护栏判为“给出了否定结论”，触发一次重写。

    产品判断

    空结果不是否定

    工具返回五种状态（ok、empty、error、degraded、unverified），而不是“有/没有”。“查不到”必须写成“未能核实”。

    结论不能比证据强

    置信度上限取最弱的关键证据。上限低于 0.5 时，护栏禁止输出“可行”或“不可行”。

    确定性的事不交给 LLM

    坐标、规则表、容积估算由代码完成。关闭 LLM 的基线 1.3 秒、$0，得出相同结论。

    兜底不能吞掉缺陷

    v2 的公交工具一直在报错，却被 catch-all 变成了“少一块的正常回答”。现在异常必须进入证据和评测。

    护栏也要评估

    非注入运行中护栏拦截了 3 条，全部是误报，每次多花约 $0.04。护栏现在有自己的 10 条测试用例。

    仍未解决

    评测集只有 19 个场景；只覆盖一个城市；“咖啡馆”到条例用途分类的映射需要人工审核；工具内容中的提示注入还没有防护。
